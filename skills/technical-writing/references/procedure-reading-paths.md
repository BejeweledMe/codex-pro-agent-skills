# Procedure reading paths

Use this for instructions with advance preparation, overlapping phases, ambiguous spatial details, or readers returning at an intermediate step. It supplements the documentation contract; it does not replace technical verification or domain requirements.

## Walk actions as the reader encounters them

Simulate a reader acting while reading. At each step, check whether the required resource, permission, preparation, and state would be available then. Move preparation to the point where it must begin and retain a readiness check before the dependent action. Do not assume readers scheduled the whole procedure in advance.

Hypothetical defect: step 1 asks readers to compare a current export with a prior export; step 4 first says to request the prior export from its owner. Requesting that export belongs before comparison begins. If independent work is permitted while waiting, an overview can identify it; do not invent concurrency where the underlying system requires serial execution. Preserve the documented date or version requirement if export freshness matters.

Distinguish starting preparation from completing it. A submission confirmation does not prove a resource is ready. Use the documented success signal and failure path, not an invented elapsed-time threshold. If that signal is absent, flag the missing fact rather than fabricate a readiness check.

## Preserve conditions at re-entry

Readers may return days later or follow a direct link. Read a section's title and first instruction without the introduction. Keep identity, scope, prerequisites, and safety conditions available wherever losing them could change the action. Link to a stable prerequisite section when that provides usable access; repeat a short critical condition when a link would be insufficient.

A phase overview can show where the reader is and which earlier state is assumed. A technical reference may need deep hierarchy; flatten it only when retrieval improves without losing the contract. Repetition that preserves a governing condition is not verbal noise. A prohibition does not imply that the opposite state is sufficient permission to act; keep the actual authorization and readiness conditions.

## Resolve spatial ambiguity with evidence

When words leave object identity, location, orientation, or an error-prone movement unclear, select a verified screenshot, diagram, or photograph that resolves that problem. A closeup, labeled part, direction arrow, or comparison with the incorrect orientation can each serve a different need.

Describe what the aid must establish. An attractive overall image may fail to show the identifier needed for the step. Keep necessary warnings and textual instructions; a visual does not prove that the procedure is complete, accessible, or safe in every setting.

Use the correct system or document version and actual labels. An unavailable screenshot can be listed as a needed asset; it must not be described as inspected. Obtain technical facts from the responsible owner or verified artifacts. A writing pass can reveal a missing fact without authorizing execution of the documented action.
