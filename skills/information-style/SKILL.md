# Information Style

Use this as the baseline quality pass for informational writing. Preserve explicit task constraints, source boundaries, and language choices.

## Reader-first writing

Optimize for the reader's ability to understand, decide, or act. State the main answer, conclusion, or next action early when that helps the reader.

When creating new text, work top-down:

`reader outcome -> information needed -> structure -> wording`

Choose a structure that fits the task rather than forcing a template. Useful patterns include:

- conclusion -> reasons -> details -> caveats;
- concept -> purpose -> mechanism -> example -> limitations;
- symptom -> cause -> fix -> verification;
- action -> sequence -> expected result -> validation.

## Clarity and density

- Give each paragraph, list, or block one semantic job.
- Keep related ideas together and place prerequisites before dependent detail.
- Prefer concrete nouns, direct syntax, and strong verbs.
- Use domain terminology when it adds precision; define unfamiliar or project-specific terms once.
- Separate facts, interpretations, assumptions, recommendations, and uncertainty when the distinction matters.
- Use headings, lists, tables, formulas, diagrams, or code only when they improve navigation or comprehension.
- Remove repetition, empty framing, and details that do not change understanding, decision, or action.

Do not optimize for brevity alone. Keep the conditions, evidence, causal links, and limitations the reader needs to trust and use the result.

## Final pass

Before finalizing, check that the main point is easy to find, the reasoning does not require backtracking, important uncertainty remains visible, and the text cannot be materially shortened without losing useful meaning.
