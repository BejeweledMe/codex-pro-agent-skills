# Nontechnical Audience

Adapt the selected operation or artifact for a reader who is unfamiliar with the domain. Optimize for practical understanding while preserving factual correctness.

## Emphasis

Prefer this order when it fits:

`practical meaning -> why it matters -> simple mechanism -> consequence -> necessary nuance`

Use plain language when it preserves meaning. When a technical term is necessary, name it, define it in a short phrase, and continue using the correct term if it will recur. Translate implementation detail into observable consequences, but retain technical evidence that changes a decision or explains a limitation.

Use one concrete example or carefully bounded analogy when it materially reduces abstraction. Avoid jargon, black-box claims, and simplifications that erase an important condition or trade-off.
